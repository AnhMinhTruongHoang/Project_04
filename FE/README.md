## 📖 Overview

SoundClone is a modern music streaming and creator platform inspired by the interaction model of large music communities.

The frontend is built with **Next.js**, **React**, **TypeScript**, **Material UI**, and **NextAuth**. It communicates with the SoundClone Spring Boot backend through REST APIs.

The application provides listeners, artists, and administrators with dedicated experiences including music discovery, track playback, artist profiles, creator tools, subscription plans, fan memberships, ticketed events, notifications, creator earnings, payouts, and moderation.

---

## ✨ Main Features

- User authentication and account management
- Music discovery and track streaming
- Global music player
- Track details, likes, comments, and listening history
- Artist and user profiles

- Notifications
- Profile badges
- Artist wallet and payout management
- Administrator dashboard and moderation tools
- Responsive dark-mode interface
- Mobile client integration with the same backend

```text
http://localhost:8000
```

Open the Frontend directory:

```bash
cd FE
```

```bash
npm install
```

---

# 🔐 Environment Variables

Create `.env.local` or `.env.development` inside `FE`.

Example:

```env
NEXT_PUBLIC_BACKEND_URL=http://localhost:8000
NEXTAUTH_URL=http://localhost:3000
NEXTAUTH_SECRET=your_nextauth_secret
REVALIDATE_SECRET=your_revalidate_secret
NEXT_PUBLIC_SITE_URL=http://localhost:3000
TOKEN_EXPIRE_NUMBER=30
TOKEN_EXPIRE_UNIT=days
```

> Never commit real secrets, production credentials, access tokens, refresh tokens, OTP values, payment secrets, or OAuth secrets to GitHub.

After changing environment variables, restart the Next.js development server.

# ⏳ Backend Startup Loader

SoundClone can display a full-screen startup loader while the Spring Boot Backend is cold-starting.

The loader:

- Uses the SoundClone logo
- Polls the Backend
- Shows game-style progress
- Stops fake progress before 100%
- Reaches 100% only after the Backend responds
- Shows a slow-start message if startup takes longer than expected
- Allows the user to retry the connection

This makes long backend startup times clearer to the user.

# 🔗 Backend Connection

The Frontend expects:


The REST API generally uses:

```text
/api/v1/...
```

Examples:

```text
GET  /api/v1/auth/account
GET  /api/v1/tracks
GET  /api/v1/tracks/top
GET  /api/v1/subscriptions/plans
GET  /api/v1/notifications
GET  /api/v1/tickets/me
POST /api/v1/payments/vnpay/create
```

# 🛠️ Common Issues

## Backend is still starting

Keep the frontend page open. The startup loader can continue checking automatically.

Backend:

```text
http://localhost:8000
```

---

## Login does not work

Confirm:

```env
NEXT_PUBLIC_BACKEND_URL=http://localhost:8000
```

Then restart:

```bash
npm run dev
```

---

## Tracks do not load

Test:

```text
http://localhost:8000/api/v1/tracks/top?category=ncs
```

If JSON is returned, inspect the browser Network tab and verify the Frontend is calling the correct Backend URL.

---

## Environment variables are not applied

Restart:

```bash
npm run dev
```

---

## `404 No static resource api/v1/...`

This usually means the request is going to the wrong server.

Check:

```env
NEXT_PUBLIC_BACKEND_URL=http://localhost:8000
```

# 🔄 Frontend ↔ Backend Flow

```text
User Interaction
      ↓
Next.js Component / Page
      ↓
Frontend API helper
      ↓
Spring Boot REST API
      ↓
Service / Business Logic
      ↓
Database
      ↓
ApiResponse
      ↓
Frontend State
      ↓
Updated UI
```

Payment-backed features use Backend-confirmed state rather than trusting only browser redirects.

# 📌 Development Principles

1. Do not hardcode the Backend URL.
2. Keep user-facing text consistent.
3. Keep the interface dark-mode compatible.
4. Verify responsive behavior.
5. Avoid duplicate API requests.
6. Do not trust frontend-only permission checks.
7. Use Backend-confirmed payment state.
8. Handle loading, empty, error, and success states.
9. Keep shared API logic centralized.
10. Run a production build before merging important changes.
