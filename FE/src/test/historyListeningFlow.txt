4. Chuẩn hóa helper trong src/utils/api.ts
Sửa getTrackId
export const getTrackId = (track?: any) => {
  return track?.id || track?._id || "";
};
Sửa normalizeTrack
export const normalizeTrack = <T extends any>(
  track?: T | null
): T | null => {
  if (!track) return null;

  const id = String(
    (track as any).id ||
      (track as any)._id ||
      ""
  ).trim();

  return {
    ...track,
    id,
    _id: id,
    imgUrl: (track as any).imgUrl,
    trackUrl: (track as any).trackUrl,
  };
};

Điều này tránh trường hợp _id cũ ghi đè lên id mới.

7. Slug Track

Slug được tạo theo công thức:

slugify(title) + "-" + 6 ký tự đầu của ID

Ví dụ:

Title: Domino
ID: cae6613f56054e4b9fed57a8
Slug: domino-cae661

Backend helper:

private String createSlug(String title, String id) {
    String suffix =
        id.length() >= 6
            ? id.substring(0, 6)
            : id;

    return slugify(title) + "-" + suffix;
}

30. Kết quả cuối cùng mong muốn

Luồng hoàn chỉnh:

User chọn một track
        ↓
Route dùng slug hoặc ID mới
        ↓
Track detail mở thành công
        ↓
AppFooter hoặc WaveTrack phát audio
        ↓
TrackContext cập nhật currentTime và duration
        ↓
Frontend lưu tiến trình mỗi 15 giây
        ↓
Backend insert/update listening_histories
        ↓
Homepage tải dữ liệu theo tài khoản
        ↓
Hiển thị:
- Continue Listening
- Recently Played
- Because You Listened To
- Hidden Gems
- Top category sliders
31. Ghi chú kỹ thuật
Tất cả helper track ID cần ưu tiên id trước _id.
Không dùng updatedAt để xác định track mới vì lượt phát hoặc thao tác admin có thể cập nhật field này.
Không gửi progress API mỗi giây.
Không dùng Admin preview audio làm listening history.
Track phải APPROVED và isDeleted = false mới xuất hiện public.
Next.js Server Component request cần cache: "no-store".
Khi dữ liệu route có vẻ cũ, phải xóa .next.
Backend hiện chưa dùng service layer riêng cho Track.
