Dự án: SoundCloud Clone
Phạm vi: Backend + Frontend
Trạng thái: Đã hoàn thành phần lõi, cần kiểm thử runtime và tiếp tục gắn các trigger nghiệp vụ còn lại
Ngày cập nhật: 15/07/2026

============================================================
1. MỤC TIÊU MODULE
============================================================

Module thông báo được xây dựng để:

- Lưu thông báo theo từng người nhận.
- Hiển thị số lượng thông báo chưa đọc trên icon chuông.
- Hiển thị danh sách thông báo nhanh bằng popup ở Header.
- Có trang /notifications để xem toàn bộ lịch sử thông báo.
- Hỗ trợ đánh dấu đã đọc, đánh dấu tất cả đã đọc và xóa thông báo.
- Điều hướng người dùng đến đúng track, user hoặc màn hình liên quan.
- Chống tạo trùng thông báo bằng deduplicationKey.
- Không tạo thông báo khi người thực hiện hành động cũng là người nhận.
- Có khả năng mở rộng cho Follow, Like, Comment, kiểm duyệt track, bản quyền, subscription và quota.

2.2. Cấu trúc dữ liệu Notification

Các trường chính:

- id
- recipientId
- actorId
- type
- title
- message
- entityType
- entityId
- redirectUrl
- metadataJson
- isRead
- readAt
- deduplicationKey
- createdAt
- updatedAt

Ý nghĩa:

- recipientId: người nhận thông báo.
- actorId: người tạo ra hành động.
- entityType và entityId: đối tượng liên quan như TRACK, USER, COMMENT hoặc SUBSCRIPTION.
- redirectUrl: đường dẫn frontend khi người dùng bấm vào thông báo.
- metadataJson: dữ liệu bổ sung để frontend mở rộng sau này.
- deduplicationKey: khóa chống tạo thông báo trùng.
- isRead và readAt: trạng thái đọc.
- createdAt: thời điểm thông báo được tạo hoặc được đẩy lại lên đầu khi event lặp lại.

2.4. API backend đã có

GET /api/v1/notifications?page=0&size=20&status=all

Mục đích:
- Lấy danh sách thông báo của user hiện tại.
- Có phân trang.
- status hỗ trợ all hoặc unread.

GET /api/v1/notifications/unread-count

Mục đích:
- Lấy số lượng thông báo chưa đọc.
- Dùng cho badge trên icon chuông.

PATCH /api/v1/notifications/{notificationId}/read

Mục đích:
- Đánh dấu một thông báo là đã đọc.

PATCH /api/v1/notifications/read-all

Mục đích:
- Đánh dấu toàn bộ thông báo của user hiện tại là đã đọc.

DELETE /api/v1/notifications/{notificationId}

Mục đích:
- Xóa một thông báo thuộc user hiện tại.

DELETE /api/v1/notifications/clear-read

Mục đích:
- Xóa toàn bộ thông báo đã đọc của user hiện tại.

2.5. Quy tắc bảo mật đã áp dụng

- User được lấy từ JWT Bearer Token.
- Mọi thao tác đọc, sửa hoặc xóa đều gắn với recipientId của user hiện tại.
- User không thể đọc hoặc xóa thông báo của user khác.
- Không gửi thông báo cho chính actor nếu actorId bằng recipientId.
- NotificationRepository sử dụng findByIdAndRecipientId để giới hạn quyền truy cập.

2.6. Flow Comment đã được gắn

Nơi gắn đúng:

TrackController.java

Endpoint tạo comment:

POST /{trackId}/comments

Sau khi lưu comment:

Comment savedComment = commentRepository.save(comment);

Backend gọi:

notificationService.notifyTrackComment(
    user,
    track,
    savedComment
);

Kết quả:

- User B comment vào track của User A:
  + Comment được lưu.
  + User A nhận notification loại TRACK_COMMENT.
  + unreadCount của User A tăng lên.
- User A tự comment vào track của mình:
  + Comment vẫn được lưu.
  + Không tạo notification cho chính User A.
- Mỗi comment dùng deduplicationKey:
  TRACK_COMMENT:{commentId}
- Một comment chỉ tạo tối đa một notification.

2.7. CommentController hiện tại

CommentController hiện chỉ phụ trách:

- GET danh sách comment cho Admin.
- DELETE comment theo dạng soft delete.

Vì vậy:

- Không cần inject NotificationService trong CommentController.
- Không cần tạo CommentService chỉ để làm notification.
- Notification được gọi tại TrackController vì đây là nơi tạo comment thật.

3.4. Switch bật/tắt notification

Nút Settings trong popup đã được thay bằng switch On/Off đơn giản.

Hiện trạng switch:

- Lưu trạng thái bằng localStorage.
- Khi Off:
  + Không load notification.
  + Không polling unread count.
  + Badge về 0.
  + Danh sách popup được làm trống.
- Khi On:
  + Load lại unread count.
  + Load lại notification.

Lưu ý quan trọng:

Switch hiện chỉ tắt notification ở phía frontend trên trình duyệt hiện tại.

Switch chưa:

- Lưu cài đặt vào database.
- Tắt việc backend tạo notification.
- Đồng bộ giữa nhiều thiết bị.
- Đồng bộ giữa nhiều trình duyệt.

Nếu muốn thành tính năng cài đặt thật, cần thêm notificationEnabled trong User hoặc UserSetting và có API backend cập nhật trạng thái.

============================================================
4. FLOW HOẠT ĐỘNG HIỆN TẠI
============================================================

Flow Comment:

1. User B đăng nhập.
2. User B comment vào track của User A.
3. TrackController lưu Comment.
4. NotificationService tạo TRACK_COMMENT.
5. Notification được lưu với recipientId là User A.
6. Header của User A gọi unread-count.
7. Badge chuông hiển thị số chưa đọc.
8. User A mở popup.
9. Popup gọi API lấy danh sách notification.
10. User A bấm notification.
11. Frontend gọi API mark read.
12. Badge giảm.
13. Frontend điều hướng đến redirectUrl.
14. User A có thể xem toàn bộ lịch sử tại /notifications.

============================================================
6. CÁC VIỆC CÒN LẠI
============================================================

Ưu tiên 1: Xác nhận flow Comment chạy runtime

- Build backend.
- Test comment bằng hai user.
- Kiểm tra notification được insert.
- Test API unread count.
- Test Header và page.

Ưu tiên 2: Gắn notification Follow

Khi User B follow User A:

- recipientId = User A.
- actorId = User B.
- type = NEW_FOLLOW.
- entityType = USER.
- entityId = User B.
- redirectUrl = profile của User B.
- deduplicationKey:
  NEW_FOLLOW:{actorId}:{recipientId}

Ưu tiên 3: Gắn notification Like

Khi User B like track của User A:

- recipientId = User A.
- actorId = User B.
- type = TRACK_LIKE.
- entityType = TRACK.
- entityId = trackId.
- redirectUrl = route track.
- deduplicationKey:
  TRACK_LIKE:{trackId}:{actorId}

Ưu tiên 4: Gắn notification kiểm duyệt track

Khi Admin duyệt hoặc từ chối track:

- TRACK_APPROVED.
- TRACK_REJECTED.
- COPYRIGHT_APPROVED.
- COPYRIGHT_REJECTED.
- TRACK_PROCESSING_COMPLETED.

Người nhận là uploader của track.

Ưu tiên 5: Gắn notification Subscription và Quota

Các thời điểm:

- Đổi plan.
- Hủy gia hạn.
- Gia hạn thành công.
- Sắp hết hạn.
- Dùng gần hết upload quota.
- Vượt upload quota.

Nên dùng deduplicationKey theo subscription period để tránh spam.

Ưu tiên 6: Đồng bộ switch notification với backend

Nếu cần cài đặt thật:

- Thêm notificationEnabled vào User hoặc UserSetting.
- API:
  GET /api/v1/users/me/notification-settings
  PATCH /api/v1/users/me/notification-settings
- Backend kiểm tra setting trước khi tạo notification.
- Frontend không chỉ dùng localStorage.
- Cài đặt đồng bộ trên mọi thiết bị.
